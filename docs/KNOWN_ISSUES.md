# V1.2 当前已知问题

本文件只记录当前仍存在的问题。已经修复的配置、解析和测试问题统一记录在
[CHANGELOG.md](../CHANGELOG.md)，不在这里保留历史过程。

## 1. 普通个人微信通道不稳定

`integrations/wechat-bot` 使用 `wechaty-puppet-wechat4u` 模拟微信网页版协议。很多微信号没有网页版
登录权限；即使能够扫码登录，也可能掉线、收到安全警告或被限制。

代码无法绕过腾讯侧账号权限。该通道只适合专用小号实验，不能作为稳定生产入口。生产环境优先使用
微信公众号，具体方式见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 2. 公众号仍需真实公网验收

仓库已有固定域名部署模板和自动化 XML 回调测试，但服务器、域名、DNS、微信后台配置、平台重试以及
公网网络质量必须在真实环境验证。完成部署后应人工验收：

- 订阅和首次授权；
- 资料确认与餐食、训练记录；
- 同一消息重试的幂等行为；
- 超时后的“结果”查询；
- 日志中不出现 Token、原始 OpenID 或用户消息正文。

## 3. 微信 AES 安全模式尚未实现

当前公众号模板要求明文消息模式，并依赖 HTTPS 保护传输。若微信后台切换到
`encrypt_type=aes`，项目尚未实现消息体加解密和签名验证，回调将无法正常处理。

## 4. 食物目录仍有覆盖边界

目录以公开食物成分数据为主，部分数据是生重，熟食、餐馆菜、地方菜和品牌食品仍可能缺失。系统会对
目录外食物调用 DeepSeek 估算并标记 `estimated`；包装食品仍以用户提供的标签为更高优先级。模型估算
会受到实际配方、烹饪用油和份量差异影响。

## 5. 模型服务属于可选外部依赖

DeepSeek 可能因网络、额度、响应格式或服务状态不可用。系统会降级到目录和规则解析；此时目录外食物
无法自动估算，建议稍后重试。越过营养范围校验的估算不会写入数据库。

## 建议优先级

1. 在真实服务器和固定域名上完成公众号验收。
2. 根据微信后台配置决定是否实现 AES 安全模式。
3. 根据真实记录比较模型估算与包装标签或可靠食物数据，持续校准提示词和范围校验。
4. 评估是否继续维护非官方个人微信实验通道。
